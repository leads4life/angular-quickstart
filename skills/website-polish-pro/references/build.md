# Build pattern: one template, one builder, many pages

Keep the site as source files plus a build script, so any turn (or a reset container) can resume from files, not memory.

```
site/
  template.html     header, footer, home <main>, shared <style>, SVG sprite, one <script>; markers <!--HEADER-->…<!--/HEADER--> etc.
  pages/<key>.html  inner page bodies (start with a .page-hero), pages/_band.html shared closing band
  pages.css legal.css seams.css (seams.css generated by scripts/deco.py)
  pages.js          TOC scroll-spy, filter chips, hours "open now" (business time zone if known), demo forms
  img/              one file per photo slot (see photography.md)
  site.py           builder → dist/
```

## Builder rules (site.py)
- `PAGES = {key: (filename, body_file, title)}`; home body = template's own `<main>`.
- Every internal link is a token `href="@@key@@"` (anchors allowed: `@@contact@@#hours`). Resolve with `re.sub(r"@@(\w+)@@", …)` and assert no `@@` remains. Link to files (`about.html`), never bare folders, so the zip works from disk.
- Mark the current page: replace `href="@@key@@"` with `href="@@key@@" aria-current="page"` in header and footer before resolving.
- Never rewrite `<use href="#symbol">`.
- **Single switches** for facts that will change: `ORDER_URL = ''` (empty → fall back to the on-site "how to order" anchor), booking URL, etc. Use a dedicated token (`@@order@@`) for every button that depends on it.
- Inject shared pieces per page instead of copying them: the hero-exit wave into each `.page-hero`, the closing band, a localized eyebrow label per page (e.g. `ZH_EYEBROW = {'menu': '菜單', …}`).
- Wrap feature photos for shapes in the build step: `<figure class="frame"><img>` → `<figure class="frame"><div class="blob" data-shape="a|b|c"><img></div>`, cycling a/b/c with a per-page offset.
- CJK font subset: after building every page, collect the CJK characters used and fill `&text=%%CJK%%` in the Google Fonts link.
- JSON-LD (`Restaurant`/`LocalBusiness`) built only from facts already on the page (name, address, phone, hours).
- Output full `<!DOCTYPE html>` documents; `index.html` is home. Publish all files (plus `img/`) as one multi-file artifact; zip the same folder with README.md and PHOTOGRAPHY.md.

## Layout rules learned the hard way
- One content column: every section's container shares the same `max-width` and side padding (e.g. `--wrap:1180px`, padding `clamp(16px,4vw,40px)`). Headers may be wider. Split full-bleed bands get `data-align="free"`, but their text still aligns to the column.
- One vertical spacing scale (e.g. `.sec{padding:clamp(60px,8vw,100px) 0}` plus one tight variant); heights follow content.
- Card grids: choose column counts that divide the item count at every breakpoint (6 → 3/2/1; 4 → 4/2/1). `repeat(auto-fit,minmax())` produces orphans at tablet widths; use explicit modifier classes (`.values.three`).
- Two-column rows (text + form, text + photo): fill the shorter side with useful content (a checklist, hours, a call line) instead of leaving a void.
- Inline `style=""` beats every media query; grep for it.
- Decorations that run past the page edge need `overflow-x:clip` (not hidden) on their section, header included.
- `[hidden]{display:none!important}` always.
